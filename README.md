# Програмний проєкт №2

Дослідження швидкодії бібліотечних алгоритмів C++ (`std::execution` policies) та
власного паралельного алгоритму. **Варіант 6** — скалярний добуток
(`std::inner_product`; з політиками — `std::transform_reduce`).

**Виконавець:** Корпачов Артем Андрійович (виконується одноосібно).
Група К-27, 2 курс, факультет комп'ютерних наук та кібернетики КНУ імені Тараса
Шевченка, спеціальність F3 «Комп'ютерні науки», освітня програма «Інформатика».
Дисципліна: «Програмування мовою C++. Додаткові розділи».

Результати досліджень та висновки — у звіті **[report.pdf](report.pdf)**.
Цей файл описує, як зібрати й запустити програму та який формат мають дані.

## Що вимірюється

Усі експерименти — це скалярний добуток двох послідовностей `double`.
Кожен час — **медіана кількох запусків** (7 для експериментів 1–2, 15 для експерименту 3).

1. `std::inner_product` без політики виконання.
2. `std::transform_reduce` з політиками `seq`, `par`, `par_unseq`.
3. Власний алгоритм `parallel_dot_product`: послідовність ділиться на K приблизно
   однакових частин, кожну частину в окремому потоці обробляє `std::inner_product`,
   часткові суми зводить `std::reduce`. Виводиться таблиця часу для різних K,
   найкраще K та його відношення до `std::thread::hardware_concurrency()`.
4. Вплив рівня оптимізації: ті самі експерименти у двох збірках Release —
   `/O2` (максимальна оптимізація) і `/Od` (без оптимізації).

Перед експериментами програма перевіряє, що всі алгоритми дають однаковий
результат на одних і тих самих даних.

## Вимоги

* C++23, MSVC 19.51.36260 (Visual Studio 2026 / Build Tools v18.10.3);
  компілятор також указано в коментарі на початку `src/main.cpp`.
* CMake 3.25+, Ninja, x64. Дослідження виконуються **лише в режимі Release**.

## Збирання

У **x64 Native Tools Command Prompt for VS 2026** (там має бути рядок
`Environment initialized for: 'x64'`):

```bat
cd C:\Projects\ProgProj2

cmake --preset x64-release
cmake --build --preset x64-release

cmake --preset x64-release-noopt
cmake --build --preset x64-release-noopt
```

| Пресет | Режим | Прапорці оптимізації |
| --- | --- | --- |
| `x64-release` | Release, максимальна оптимізація | `/O2` |
| `x64-release-noopt` | Release без оптимізації | `/Od` |

## Запуск

Програму запускають **з теки проєкту**, бо дані шукаються у `data\`.

```bat
build\x64-release\ProgrammingProject2.exe --generate
build\x64-release\ProgrammingProject2.exe --run > results_O2.txt
build\x64-release-noopt\ProgrammingProject2.exe --run > results_Od.txt

rem повторний прогін /O2 для перевірки стабільності
build\x64-release\ProgrammingProject2.exe --run > results_O2_repeat.txt
```

| Аргумент | Дія |
| --- | --- |
| `--generate` | Генерує послідовності й зберігає їх у `data\` (один раз). |
| `--run` | Виконує перевірку коректності та експерименти 1–3, друкує таблиці. |

Обидві збірки використовують **однакові файли з `data\`**. Для перенаправлення
виводу використовуйте `cmd` (Developer Command Prompt): у Windows PowerShell 5.1
оператор `>` зберігає файл у UTF-16.

## Формат вхідних даних

Послідовності генерує `std::mt19937` (seed = 42) з рівномірним розподілом
`std::uniform_real_distribution<double>(0, 1)`. Розміри: 100 000, 1 000 000,
5 000 000, 10 000 000 та 20 000 000 пар. Кожен розмір зберігається в окремому текстовому
файлі `data\sequence_<N>.txt`:

```text
<N>
<a_1> <b_1>
<a_2> <b_2>
...
<a_N> <b_N>
```

Перший рядок — кількість пар `N`, далі `N` рядків із двох дійсних чисел через
пробіл (7 значущих цифр). Перша послідовність — це числа `a_i`, друга — `b_i`.
Файли займають близько 700 МБ, тому тека `data\` не додається до репозиторію
(див. `.gitignore`) і відтворюється командою `--generate`.
